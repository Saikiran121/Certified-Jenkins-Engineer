# Demo: Working with Freestyle Projects (ASCII Artwork)

In this hands-on demo, we will create a fun and interactive Jenkins project that fetches random advice from a REST API and renders it as ASCII artwork using a cow.

---

## 1. Project Configuration Steps

1.  **Create New Item:**
    - Click **New Item** on the Jenkins Dashboard.
    - **Name:** `generate ASCII Artwork`
    - **Type:** Select **Freestyle project**.
    - Click **OK**.

2.  **General Settings:**
    - **Description:** `Generate ASCII Artwork using Cowsay library and AdviceSlip Rest API`
    - **Build Environment:** Check **Add timestamps to the Console Output**. (This helps in debugging performance).

3.  **Source Code Management:**
    - Select **None**. (We are writing a standalone script, so no Git repository is needed for this demo).

4.  **Build Steps:**
    - Click **Add build step** > **Execute shell**.
    - Paste the following block into the **Command** area:

```bash
# Fetch advice
curl -s https://api.adviceslip.com/advice > advice.json
cat advice.json

# Extract advice
jq -r '.slip.advice' advice.json > advice.message

# Validate word count
if [ "$(wc -w < advice.message)" -gt 5 ]; then
  echo "Advice has more than 5 words"
else
  echo "Advice - $(cat advice.message) - has 5 or fewer words"
  exit 1
fi

# Generate ASCII art
/usr/games/cowsay -f "$(ls /usr/share/cowsay/cows | shuf -n 1)" "$(cat advice.message)"
```

---

## 2. Deep Dive: What does the Shell Script do?

This script is a perfect example of a **CI Task**: it fetches data, processes it, validates it with logic, and produces an output.

### Line-by-Line Breakdown:

1.  **`curl -s https://api.adviceslip.com/advice > advice.json`**: 
    - Fetches a random piece of advice in JSON format from a public API.
    - `-s` (silent) prevents progress bars from cluttering the Jenkins logs.

2.  **`jq -r '.slip.advice' advice.json > advice.message`**:
    - **jq** is a command-line JSON processor. It reads `advice.json`, extracts the `.slip.advice` field, and saves the raw text (`-r`) to a new file.

3.  **The `if` condition (`wc -w`)**:
    - This is a **Quality Gate**. It counts the number of words in the message.
    - If the advice is too short (5 words or fewer), the script returns `exit 1`.
    - **Jenkins Logic:** In any shell step, `exit 1` (or any non-zero code) tells Jenkins that the **Build has FAILED**.

4.  **`/usr/games/cowsay -f "$(ls ... | shuf -n 1)" "$(cat advice.message)"`**:
    - **Full Path:** We use `/usr/games/cowsay` to ensure the binary is found even if `/usr/games` isn't in the Jenkins user's `$PATH`.
    - **`$(ls /usr/share/cowsay/cows | shuf -n 1)`**: Lists all available "cow" characters and randomly picks one.
    - **`"$(cat advice.message)"`**: Passes the text of the advice as an argument to the `cowsay` command to render the final artwork.

## 3. Verifying Results on the Server (The Workspace)

While the Jenkins UI shows the **Console Output**, a DevOps engineer often needs to verify the actual files generated on the server's disk. This is done in the **Workspace**.

Every Jenkins project has a dedicated folder where it does its work. By default, on Linux, these are located in: `/var/lib/jenkins/workspace/`

### CLI Investigation:

Open your terminal and follow these steps to see the "DNA" of your build:

```bash
# 1. Navigate to the global Jenkins workspace directory
cd /var/lib/jenkins/workspace/

# 2. List the contents to find your project folder
ls
# Output: 'generate ASCII Artwork'

# 3. Enter your project's workspace
cd 'generate ASCII Artwork'/

# 4. List the files generated by your script
ls
# Output: advice.json  advice.message

# 5. Inspect the raw JSON data
cat advice.json 
# Output: {"slip": { "id": 204, "advice": "The best nights out are when people around you are simply having fun."}}

# 6. Inspect the extracted text message
cat advice.message 
# Output: The best nights out are when people around you are simply having fun.
```

### Why this matters:
- **Persistence:** Even if you delete a build's history in the UI, the files in the workspace might remain until the next build runs.
- **Debugging:** If a script fails to "Extract JSON", you can manually `cat` the file on the server to see if the API actually returned valid data.
- **Security:** You can verify that sensitive files (like temporary credentials) are being deleted correctly by your script.

## 4. Verifying Results via Jenkins UI (The Easy Way)

If you don't have SSH/CLI access to the server, or if you just want a quick look, Jenkins provides a web-based file browser for the workspace.

### UI Investigation:

1.  Navigate back to your project dashboard (**generate ASCII Artwork**).
2.  In the left-hand sidebar, click on **Workspace**.
3.  You will see a live file listing of the project folder on the server.
4.  **Click on `advice.message`** or **`advice.json`**.
5.  Jenkins will render the text content of those files directly in your browser.

### UI vs. CLI Comparison:

| Feature | Jenkins UI (Workspace) | CLI (/var/lib/jenkins/...) |
| :--- | :--- | :--- |
| **Effort** | Low (One click). | Medium (Requires terminal). |
| **Permissions** | Jenkins User account. | Linux OS account. |
| **Interactivity** | Read-only. | Full control (edit, delete, move). |
| **Visualization** | Text display in browser. | Power of `grep`, `jq`, and `awk`. |

## 5. How to Verify Success (UI Console)

1.  Click **Build Now** on the project page.
2.  Once the build finishes (Blue circle), click on the build number (e.g., `#1`).
3.  Select **Console Output**.
4.  **Expected Result:** You should see a timestamped log showing the JSON data, the word count validation, and finally, a randomly selected ASCII animal "speaking" your advice!
